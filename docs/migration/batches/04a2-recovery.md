# 04а2 — заявка на восстановление доступа

Статус: локальная ветка реализована и проверена 6 ноября 2026. Весь контур доступа 04а–г ещё не закрыт.

## Свежий источник

Figma `f58CsE8Ix5Win8LQnr0poq`, A4 `34:175`: 6 ноября прочитаны текущие узлы, реакции и свежий render. Форма `79:636`, контакт `79:637`, доступная почта `193:322`, пояснение `193:326`, отправка `79:642`, подтверждение `193:327`, возврат `2020:502`.

В источнике отправка заявки не восстанавливает доступ: подтверждение владельца выполняется отдельно. Не выдавать сессию и не менять контакт входа по результату этой формы.

## Покрытая ветка

Вход или OTP → восстановление с сохранённым контактом → обязательные поля / исправление формата → отправка → подтверждение → вход. Переход к восстановлению отменяет прежний challenge. Новое начало очищает прошлую заявку и доступную почту. Во время запроса повторная отправка заблокирована; уход отменяет поздний результат. Ошибка адаптера допускает повторную попытку.

После перезагрузки подтверждение восстанавливается только по валидной квитанции этой вкладки. Прямая ссылка без квитанции возвращает форму. Квитанция не даёт доступ к кабинету. Незавершённая форма после перезагрузки очищается; внутри текущей сессии переходов контакт сохраняется.

## Явные адаптации

- Редактируемые поля и проверка формата вместо предзаданных значений; async loading, отмена и retry для будущего адаптера.
- Успешное состояние выделено в URL `screen=recovery-result`: форма скрывается, подтверждение становится заголовком и описанием с фокусом. Это адаптация исходного контейнера подтверждения, не заявление о пиксельном совпадении.
- RU/EN, мобильная ширина, текущие зелёные/оранжевые токены. Кнопка использует материал плашек выбранной темы. Возврат — существующая Iconity-стрелка с поворотом.

## Проверки

- Браузер: переходы из login и OTP, сохранение контакта, пустая доступная почта, неверная почта, исправление; смена RU → EN с заполненными полями; Enter; disabled loading; отправка и возврат.
- Подтверждение после reload; новая вкладка с прямым URL результата возвращает форму. После результата доступ в кошелёк не выдаётся.
- Визуально обе темы desktop и формы на 320 px. Для оранжевой desktop измерены main x=400, y=108, width=640 при viewport 1440×1000. На 320 px горизонтального overflow нет; primary остаётся 44 px, подпись помещается.
- Автотесты: ошибка адаптера и retry, дубли, отмена устаревшего recovery, отмена OTP при начале recovery, формат контактов, квитанция и route guard. Эти сбои проверены модульно, не сетевыми сбоями в браузере.
- `npm test --prefix frontend`: 15/15. `npm run build --prefix frontend`: успешно.
- Независимый read-only агент `recovery_review_final`: код, состояния и тесты; блокирующих замечаний нет. Визуальная проверка выполнена оркестратором, независимого пользовательского исследования не было.
