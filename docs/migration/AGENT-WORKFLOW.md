# OraclePay — работа небольшими пакетами

Основной агент — оркестратор: выбирает следующий законченный сценарий из плана переноса, получает свежий источник Figma, назначает исполнителя, интегрирует результат и лично проверяет браузер. Предпочтение пользователя для основного агента — Astra High; агент не заявляет о переключении своей модели, если не может его выполнить.

Для ограниченных задач использовать `gpt-6.1-sol` с reasoning `medium`, коротким самостоятельным контекстом и конкретным результатом. Повышать сложность модели только при подтверждённой необходимости. Не запускать все роли на каждую правку.

| Роль | Ответственность | Результат |
| --- | --- | --- |
| web-deep-reader | Только чтение: текущее состояние, инструкции, маршруты, стек, исходники | Реализованное, пробелы, точные пути и ограничения |
| web-architect | Контракты, состояние, роутинг, i18n, риски интеграции | Короткое решение до разработки; без новой архитектуры без необходимости |
| web-frontend-dev | Единственный исполнитель назначенного участка React/TypeScript/Vite | Рабочий сценарий, адаптив, ошибки и загрузка; список файлов и проверок |
| web-design-lead | Независимая проверка через Impeccable, источник Figma и согласованную систему | Конкретные дефекты и доказательства; без самовольной смены стилистики |
| web-qa | Сначала отчёт: код, сборка, сценарии, RU/EN, адаптив и доступность | Дефекты с воспроизведением; повторная проверка исправлений |

## Порядок

Обязательный регламент приёмки — [FLOW-QA.md](FLOW-QA.md). До разработки исполнитель и QA составляют матрицу веток и ожидаемых изменений данных. Оркестратор проверяет полноту матрицы; независимый QA ищет также пропущенные и противоречивые случаи, которых нет в Figma. На тестирование и исправление выделяется отдельный этап каждого пакета, его нельзя сокращать ради количества перенесённых экранов.

1. Определить вход, результат и границы одного законченного флоу. Сначала перечислить все его ответвления: ошибки, загрузку, повтор, отмену, возврат, перезагрузку и изменение контекста. Делить работу по флоу, а не по отдельным экранам. Ссылка на заглушку не считается перенесённым ответвлением.
2. Проверить свежие экраны и реакции Figma. Разделить подтверждённые требования, разрешённые адаптации и неизвестные контракты.
3. При необходимости поручить независимое чтение и архитектуру. После решения — один разработчик. Разные агенты не редактируют один файл одновременно.
4. После реализации — независимые QA и дизайн-ревью. Основной агент проходит сценарий в браузере в обеих темах, RU/EN, на desktop и mobile, включая клавиатуру и важные состояния.
5. Исправить дефекты, повторить упавшие случаи, соседние ветки и регрессию общих компонентов в обеих темах на текущей версии. Обновить связь источник → код → проверка и открытые переходы. `NOT RUN` и `BLOCKED` не выдавать за успешную проверку; ревью кода и скриншоты не заменяют выполненный сценарный тест.
6. Отчитаться о работающем результате и ограничениях. Исходящие незавершённые зависимости означают частичную интеграцию, а не закрытый пакет.

Сохранять текущие локальные изменения. По действующему решению новые правки остаются локально: без push, публикации и обновления экспортов `Oracle/green` и `Oracle/orange`, пока пользователь отдельно не поручит это. Локальная имитация API не является серверной реализацией или проверкой безопасности.

## Полнота доступа — уточнение 6 ноября 2026

Вход с OTP и выходом — частичный срез, не закрытый контур доступа. Восстановление переносится до подтверждения заявки и возврата: заявка не восстанавливает сеанс и не меняет контакт. Регистрация переносится вместе с личным/бизнес-контекстом и ограничениями KYC/KYB; нельзя направлять новый непроверенный аккаунт в неограниченный кабинет. Смена контакта в настройках остаётся отдельным связанным флоу с подтверждением старого доверенного контакта.

Перед закрытием флоу QA сверяет каждую ветку с источником и её наблюдаемым результатом. Неизвестные серверные правила фиксируются отдельно; сообщения «ещё не перенесено» означают незавершённую интеграцию всего пакета, даже если отдельная форма работает.
